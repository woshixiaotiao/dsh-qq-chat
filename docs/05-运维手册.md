# 05 · 运维手册（部署 / 启停 / 排障 / 备份）

> 适用：Windows 10/11 + NapCat(OneBot 11) + Node 22+ + DSH。
> 原则：**桥只是本地 HTTP 进程**；不动 QQ 数据、不建系统定时器；所有操作可回滚。

## 1. 部署清单

| 项 | 要求 | 检查命令 |
|---|---|---|
| Node.js | ≥ 22（内置 fetch） | `node --version` |
| QQ NT | 独立副本供 NapCat 注入 | 任务管理器有 QQ 进程 |
| NapCat | 官方发行版可启动 | WebUI/日志无报错 |
| DSH | session-hub 可达 | `~/.dsh/session-hub.json` 存在 |
| 端口 | 3000 / 19390 / 6099 / 19391 空闲 | `Get-NetTCPConnection -LocalPort 3000,19390` |
| 令牌 | OneBot token（随机 32 位） | 两处配置一致 |

## 2. 一次性部署步骤

1. **NapCat 登录小号**：按 NapCat 官方文档启动独立客户端 → 扫码（或走 `src/napcat-qr-page.mjs` 的 `http://127.0.0.1:19391`）；确认 QQ 小号已登录；
2. **写 NapCat 网络配置**：
   ```powershell
   $node = 'C:\Program Files\nodejs\node.exe'   # 或 DSH 自带 node
   & $node src\napcat-onebot-setup.mjs --napcat-root <NapCat 目录> --bridge-config config\bot-bridge.json
   ```
   或手工照 `config/napcat-network.example.json` 改 `onebot11_<BOT_QQ>.json`（httpServers:3000 / httpClients:`http://127.0.0.1:19390/onebot`，同 token）；
3. **写桥配置**：
   ```powershell
   Copy-Item config\bot-bridge.example.json config\bot-bridge.json
   # 必改：onebot.token、trigger.allowFrom、dsh.cwd、rotation.*、balance.tokenFile、各绝对路径
   ```
   生成随机 token：`-join ((1..32) | % { '{0:x}' -f (Get-Random -Max 16) })`；
4. **启动桥并自检**：
   ```powershell
   node src\qq-bot-bridge.mjs --check
   node src\qq-bot-bridge.mjs        # 前台；生产用后台/计划任务（用户明确要求才建自动化）
   ```
5. **联调**：主号私聊小号发「在吗」→ 桥日志应出现 4 行（收到/投递/等回复/回发）；QQ 收到回复即通。

## 3. 启停顺序与注意

- **启动顺序**：NapCat（登录成功）→ 桥；
- **停止桥**：结束进程即可（无持久化副作用）；`bot-session.json`/`bot-state.json` 保留，下次接续；
- **重启 NapCat**：会掉登录态，需重新扫码；桥不用重启，NapCat 重连后事件继续推送；
- **重启 DSH 宿主**：hub 端口/token 会变；桥在启动时读取 `~/.dsh/session-hub.json`，**必须重启桥**；
- **不要**同时用普通 QQ 客户端登录同一小号（与 NapCat 副本互踢）。

## 4. 日常 SOP

| 频率 | 动作 |
|---|---|
| 每天 | 不用管；聊就行。桥空闲零成本 |
| 每周（或每 3–5 天） | 看 `D:\AI\日常\QQ机器人\README.md` 索引；想提前换段跑 `node src\qq-bot-rotate.mjs --apply` |
| 余额下降快 | `node D:\AI\DSH\tools\cost-report.mjs` 看会话成本；检查是否单段过长（轮换阈值） |
| 客户端掉线 | 重启 NapCat + 扫码；桥保持运行 |
| 更新 DSH | 更新后重启桥（hub token/端口可能变）；同步复核 `update-check.mjs` 的 asar 补丁项 |

## 5. 手动轮换

```powershell
$node = 'C:\Users\<you>\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'

& $node src\qq-bot-rotate.mjs                 # dry-run：只打印计划 + 交接件预览
& $node src\qq-bot-rotate.mjs --apply         # 真轮换（默认交付 D:\AI\日常）
& $node src\qq-bot-rotate.mjs --session <id前缀> --apply
& $node src\qq-bot-rotate.mjs --cwd D:\AI\日常 --out-dir D:\AI\日常\QQ机器人\交接 --apply
```

轮换后：`out/bot-session.json` 指向新会话；`out/bot-pending-handoff.json` 生成；下一条 QQ 消息自动带摘要。

## 6. 故障排查

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 桥启动但收不到 QQ 消息 | NapCat `httpClients.url` 不对 / token 不一致 / 桥端口被占 | 对照 `config/napcat-network.example.json`；`Get-NetTCPConnection -LocalPort 19390`；核对两处 token |
| `--check` 的 onebot 失败 | NapCat 未登录 / 3000 端口不通 / token 错 | 先看 NapCat 是否登录成功；浏览器/curl 调 `http://127.0.0.1:3000/get_login_info?access_token=...` |
| `--check` 的 hub 失败 | DSH 宿主重启后端口/token 变了 | 重启桥（启动时读 `session-hub.json`） |
| 收到消息但无回复 | `allowFrom` 不含发送者 / 群聊 `groups=false` / 已触发余额闸 / 模型超时 | 看日志 `[忽略]`/`[余额闸]`/`[DSH] 等回复超时` |
| 同一条消息回复两次 | 回调 ack 慢导致 NapCat 重推；或桥重启后内存去重丢失 | 检查日志是否重复 `[QQ]`；保持 ack 204；已知限制：跨重启无持久幂等 |
| 自己发的消息被当输入 | NapCat `reportSelfMessage:true` | 改回 `false`（配置示例已默认） |
| 轮换没发生 | 阈值未到 / 会话 running 被拒 / 路径无权限 | 看日志 `[轮换] 触发` 与 `[轮换] 失败`；`--force` 慎用 |
| 余额闸误停 | `floorYuan` 过高 / 余额端点 token 过期 | 调整 `floorYuan`；更新 `balance-widget.json` 的 token |
| NapCat 崩溃/掉线 | QQ 客户端更新、网络、扫码失效 | 重启 NapCat → 重新扫码；桥无需动 |
| 中文乱码 | cmd 终端编码 | `.cmd` 已 `chcp 65001`；日志为 UTF-8 |
| QQ 号被互踢/风控 | 同一小号多端登录、自动化频率高 | 只保留 NapCat 副本登录；降低频率；遵守条款 |

## 7. 备份与恢复

需要备份的小文件（都很小）：

```
config/bot-bridge.json          # 配置（含 token，注意保管）
out/bot-session.json            # 当前会话 id
out/bot-state.json              # 本段消息计数
D:\AI\日常\QQ机器人\交接\*.md    # 交接件（历史可读）
D:\AI\日常\QQ机器人\README.md    # 轮换索引
```

恢复：把上述文件放回原路径 → 启动桥 → `--check`。**不要**备份/迁移 `ntqq`、`napcat` 大目录（可重装/可再生，且含登录态）。

## 8. 升级与回滚

1. 备份 `src/`、`config/bot-bridge.json`、`out/*.json`；
2. 替换 `src/*.mjs` → `node src\qq-bot-bridge.mjs --check` → 重启桥；
3. 回滚：换回备份的 `src/`，重启；
4. NapCat / QQ 客户端升级后，先确认登录与 OneBot 配置未被覆盖（升级可能重置 `onebot11_*.json`）。

## 9. 令牌泄漏处置

- OneBot token 泄漏：改 NapCat 的 `httpServers/httpClients.token` + `config/bot-bridge.json.onebot.token`（两处一致）→ 重启桥；
- hub/余额 token 泄漏：由 DSH 侧重新生成后，桥重启读取；
- 任何情况下不要把 `config/bot-bridge.json`、`out/` 提交 git（`.gitignore` 已覆盖）。
